# 项目总览

## 项目定位

一个基于 TypeScript 的 2D、3D  图形渲染框架，提供**统一 API、多端渲染、效果一致**的能力：同一套业务代码可运行在 **WebGL2、WebGPU** 三种后端之上，并保证渲染效果一致。专注于 Web 平台的高性能渲染。

### 定位边界
- 只做 2D 渲染，不做 3D 渲染
- 不承担 DOM 布局、排版职责（文本仅支持基础样式与单行/简单换行）
- 场景图是核心抽象，业务通过场景图描述画面，不直接接触渲染后端

## 核心目标

### 性能目标
| 指标 | 目标 | 说明 |
|---|---|---|
| 场景规模 | 10,000+ 可渲染对象 | 静态与动态对象混合场景 |
| 帧率 | 移动端稳定 60fps | 中端 Android / iPhone，10k 对象 |
| 首帧渲染 | < 100ms | 从引擎初始化到首帧可交互 |
| 内存占用 | < 256MB | 10k 对象场景峰值 |
| 包体积 | 核心包 gzip < 100KB | ESM + tree-shaking 后 |

性能策略（随实现阶段逐步验证）：
- 可见性剔除：视锥剔除 + AABB 剔除，跳过不可见对象
- 脏标记：仅重绘变更区域/对象（Canvas 后端）
- 批处理：静态几何合并 draw call（GPU 后端）
- 对象池：复用粒子、临时几何数据，减少 GC 压力

测量方式：帧时间统计（p50 / p99）、`performance.now()` 采样、内存快照（Chrome DevTools / 移动端真机）。

### 功能目标
1. **场景图**：Container / Group 层级树、世界变换、z 排序、增删改事件通知
2. **图形渲染**：线段、矩形、圆、椭圆、多边形、星形、路径（类 Path2D，可自定义绘制）、图像、文本
3. **样式能力**：纯色填充、线性/径向渐变、图案填充、描边（线宽、线帽、虚线、miter 限制）、阴影、透明度、混合模式、裁剪
4. **变换**：平移、旋转、缩放、斜切、矩阵操作、锚点
5. **交互系统**：鼠标 / 触摸 / 触控笔，事件冒泡，命中检测，事件对象对齐 W3C Pointer Events 语义
6. **动画系统**：时间轴、关键帧、多轨道、插值器（线性/贝塞尔等）、缓动函数、完成/循环事件
7. **粒子系统**：发射器、粒子生命周期、纹理粒子、混合模式
8. **资产加载系统**：图片、JSON、纹理等，加载队列、失败回调、缓存
9. **字体系统**：字体注册、预加载、文本测量
10. **拾取系统**：几何拾取（ShapePickup）+ 颜色拾取（ColorPickup，离屏渲染）
11. **插件系统**：生命周期钩子（init / tick / render / destroy）
12. **渲染能力**：离屏渲染（RenderTexture）、多画布支持

### 质量目标
- TypeScript 严格模式（`strict: true`）
- 单元测试覆盖率 ≥ 90%
- 零运行时依赖
- 后端渲染一致性：三端截图 diff 测试（黄金样本比对）
- 性能回归基准测试（接入 CI 门禁）
- 完整类型声明，ESM + CJS 双构建，支持 tree-shaking

## 架构设计

### 多端统一渲染架构（核心难点）
Canvas 2D 是**即时模式**（每帧直接绘制），WebGL2 / WebGPU 是**保留模式**（资源常驻 GPU）。统一方案采用分层架构：

```
Scene（业务对象：图形、容器、变换）
   ↓ 场景遍历 / 世界变换 / 包围盒更新
RenderTree（世界坐标、剔除后）
   ↓ 几何细分
IR / RenderCommand（路径 → 三角形网格 等统一指令）
   ↓
Backend Adapter（可插拔）
 ├── Canvas2D  复用原生 path / fill / stroke，保留原始绘制指令
 ├── WebGL2    顶点缓冲 + 批处理
 └── WebGPU    渲染管线 + 资源池
```

关键设计点：
- **统一几何数据格式**：GPU 后端需将 Path2D 细分为三角形网格（earcut 等），Canvas 后端保留原始指令以获得原生质量
- **渲染效果一致性**：统一颜色空间（sRGB）、抗锯齿策略（Canvas 原生 AA vs GPU MSAA）、渐变/阴影的近似差异处理、描边样式对齐
- **降级策略**：运行时可探测能力，WebGPU → WebGL2 → Canvas2D 自动降级，API 不变
- **渲染循环**：`requestAnimationFrame` 驱动，脏标记增量更新，静态对象缓存，动态对象重绘

### 渲染管线
1. 场景遍历：更新世界变换与包围盒
2. 可见性剔除：视锥 / AABB 剔除
3. 指令生成：生成渲染指令并排序（painter's algorithm / z 值）
4. 批处理合并（GPU 后端）
5. 后端执行绘制
6. 拾取离屏帧（如启用 ColorPickup）

### 坐标系与约定
- 左上角为原点，y 轴向下（对齐 Canvas / DOM 惯例）
- 逻辑像素单位，渲染画布按 `devicePixelRatio` 缩放以适配高清屏
- 角度默认弧度制，可提供角度制 API（可选）

### 生命周期
- 引擎：`create → init → start(tick) → resize → destroy`
- 资源：`加载 → 缓存 → 引用计数 → 释放`
- 场景对象：`add → update → remove → destroy`

## API 设计目标
- 链式 / 命令式风格：`new Rectangle({ x, y, width, height }).fill('#f00').addTo(stage)`
- 事件 API 对齐 DOM 语义（`pointerdown` / `pointermove` / `pointerup` 等）
- 类型安全：泛型 + 严格的 option 类型定义
- 命名统一：`getX / setX`、一致的构造与回调签名
- 支持类实例与工厂函数两种创建方式（可选）

## 非功能需求

### 浏览器兼容
- 支持 Chrome / Edge / Firefox / Safari 最新两个大版本
- WebGPU 不可用时自动降级到 WebGL2 / Canvas2D，业务 API 与功能可用性不变

### 错误处理
- 资源加载失败可重试或降级（如图片失败显示占位）
- 字体加载失败回退默认字体
- 后端初始化失败抛出明确、可定位的错误信息

### 可调试性
- 分级日志：debug / info / warn / error
- 调试面板（可选插件）：帧率、draw call 数、对象数、内存

## 里程碑规划（建议）
| 阶段 | 内容 | 验收要点 |
|---|---|---|
| M1 | 数学库 + 场景图 + Canvas2D 后端渲染基础图形 | 基础图形可渲染，单测覆盖 |
| M2 | 路径/图像/文本 + 样式能力 + 拾取 | 功能完备，样式对齐 Canvas 原生 |

## 风险与开放问题
- **三端渲染效果一致性成本**：渐变、阴影、描边在 GPU 与 Canvas 上的实现存在差异，需截图对比测试兜底
- **WebGPU 生态成熟度**：浏览器覆盖有限，依赖降级策略保证可用性
- **3d 数学库去留**：纯 2D 框架基础功能不依赖，建议首版移除降低维护成本
- **文本渲染复杂度**：排版、换行、emoji 处理成本高，首版仅支持基础文本
- **粒子系统与 GPU 批处理的冲突**：粒子变化频繁，建议独立渲染通道避免破坏静态批处理

## 验收标准（示例）
- 10k 对象 demo：三端帧率达成性能目标
- 同一 demo 三端截图 diff 在阈值内（渲染一致）
- 核心模块单测覆盖率 ≥ 90%
- API 文档与类型声明完整，示例可运行
