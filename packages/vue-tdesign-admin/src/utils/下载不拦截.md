# 浏览器下载方案全集（含异步获取 URL + 防拦截）

下面按**可靠性**排序，每种都覆盖「点击 → 异步拿 URL → 自动下载 → 不被拦截」这个完整链路。

---

## 前置：理解浏览器的三道拦截关卡

| 关卡 | 触发条件 | 表现 |
|------|---------|------|
| **用户激活（User Activation）** | `window.open` 在 `await`/`setTimeout` 后调用 | 返回 `null` |
| **跨源导航权限** | `a` 标签带 `target="_blank"` 且跨域 | 点击无反应，控制台报权限错误 |
| **混合内容 / CORS** | HTTPS 页面下载 HTTP，或 `fetch` 跨域无 CORS | 静默拦截 |

**核心原则**：异步操作会打断用户激活，所以所有依赖用户手势的方案，都必须**先同步占位**，再异步填充。

---

## 方案一：`fetch` + `Blob` + `a[download]`（最通用，中小文件）

**适用**：能带 Token、能 POST、能改名、能处理异步。**唯一硬要求：目标服务器允许 CORS。**

```typescript
/**
 * 点击 → 异步拿 URL → 下载（跨域可用，需 CORS）
 * @param fetchUrl 异步获取真实下载地址的函数
 * @param fileName 保存的文件名
 */
async function downloadByBlob(
  fetchUrl: () => Promise<{ url: string; token?: string }>,
  fileName: string
): Promise<void> {
  // 1. 异步获取下载信息
  const { url, token } = await fetchUrl();

  // 2. fetch 文件（可带 Header）
  const res = await fetch(url, {
    headers: token ? { Authorization: `Bearer ${token}` } : {},
  });
  if (!res.ok) throw new Error(`下载失败: ${res.status}`);

  // 3. 转 Blob → 同源 blob: URL
  const blob = await res.blob();
  const blobUrl = URL.createObjectURL(blob);

  // 4. 触发下载（blob: 同源，download 必然生效，不跳页、不拦截）
  const a = document.createElement('a');
  a.href = blobUrl;
  a.download = fileName;
  // 注意：不要加 target="_blank"
  a.style.display = 'none';
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);

  // 5. 释放内存
  setTimeout(() => URL.revokeObjectURL(blobUrl), 3000);
}
```

**优点**：前端完全可控、能改名、能带 Token、能 POST、异步无碍
**缺点**：文件全量进内存（**大文件 OOM**）、依赖 CORS
**文件大小**：建议 **< 50MB**

## 方案二：`a` 标签直下 + 后端 `Content-Disposition`（大文件首选）

**适用**：后端能配合返回 `Content-Disposition: attachment`。**不依赖 CORS，不占内存。**

```typescript
/**
 * 点击 → 异步拿 URL → a 标签直下（大文件推荐）
 * 前提：下载地址返回 Content-Disposition: attachment
 */
async function downloadByATag(
  fetchUrl: () => Promise<{ url: string; fileName?: string }>
): Promise<void> {
  // 1. 异步获取下载地址
  const { url } = await fetchUrl();

  // 2. a 标签直接点击
  const a = document.createElement('a');
  a.href = url;
  // 跨域时 download 会被忽略，文件名由后端 Content-Disposition 决定
  // 如果同源，可以加 a.download = fileName
  // 千万不要加 target="_blank"（会触发跨源导航拦截）
  a.style.display = 'none';
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
}
```

**优点**：流式下载不占内存、支持任意大文件、支持进度、支持断点续传
**缺点**：跨域时**无法前端改名**（必须后端设 `Content-Disposition`）
**关键**：**不要加 `target="_blank"`**，否则跨域会被导航权限拦截

## 方案三：`window.open` 同步占位 + 异步导航（不推荐，易踩坑）

**适用**：需要保留窗口引用做后续操作。**但极易被拦截，且你之前就踩过 `the current window does not have permission to navigate the target frame` 的坑。**

```typescript
/**
 * 同步占位 → 异步导航（仅作参考，不推荐）
 */
async function downloadByWindowOpen(
  fetchUrl: () => Promise<string>
): Promise<void> {
  // 1. 同步阶段开空白窗口，必须显式 noopener=no 才能拿到引用
  const win = window.open('', '_blank', 'noopener=no');

  if (!win) {
    alert('请允许弹出窗口');
    return;
  }

  try {
    // 2. 异步获取 URL
    const url = await fetchUrl();
    // 3. 导航已有窗口（不是新开，不触发弹窗拦截）
    win.location.href = url;
  } catch (e) {
    win.close();
    throw e;
  }
}
```

**为什么放最后**：
- 跨源隔离策略（COOP）会让 `win.location.href` 报权限错误
- 安卓 WebView / 微信内置浏览器基本返回 `null`
- 现代浏览器对 `_blank` 默认加 `noopener`，拿引用需要显式声明

**能不用就不用，优先方案一或二。**

## 方案四：服务端代理中转（跨域 + 大文件 + 带 Token 的终极方案）

**适用**：目标域名不支持 CORS、必须带 Header、文件还大。**用你自己的服务端做中转，前端只跟同源通信。**

### 服务端（Node.js + Koa）

```javascript
// server.js
const https = require('https');
const fs = require('fs');
const Koa = require('koa');
const { createProxyMiddleware } = require('http-proxy-middleware');
const connect = require('koa2-connect');

const app = new Koa();

// 代理下载：流式转发，不占内存
app.use(
  connect(
    createProxyMiddleware({
      target: 'https://cdn.other.com',
      changeOrigin: true,
      pathRewrite: { '^/download': '' },
      // 统一注入鉴权
      onProxyReq(proxyReq) {
        proxyReq.setHeader('Authorization', 'Bearer YOUR_TOKEN');
      },
      // 确保下载头透传
      onProxyRes(proxyRes, req, res) {
        const cd = proxyRes.headers['content-disposition'];
        if (cd) res.setHeader('Content-Disposition', cd);
      },
    })
  )
);

app.use(async ctx => {
  ctx.body = 'proxy running';
});

const options = {
  key: fs.readFileSync('key.pem'),
  cert: fs.readFileSync('cert.pem'),
};

https.createServer(options, app.callback()).listen(3443, () => {
  console.log('HTTPS 代理: https://localhost:3443');
});
```

### 前端

```typescript
/**
 * 点击 → 异步拿 URL → 请求同源代理 → 下载
 * 全程同源，无 CORS、无跨域导航、无混合内容
 */
async function downloadByProxy(
  fetchUrl: () => Promise<{ url: string; fileName: string }>
): Promise<void> {
  const { url, fileName } = await fetchUrl();

  // 把外部 URL 编码后交给同源代理
  const proxyUrl = `/download?target=${encodeURIComponent(url)}`;

  const a = document.createElement('a');
  a.href = proxyUrl;           // 同源地址
  a.download = fileName;       // 同源，download 生效，能改名
  a.style.display = 'none';
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
}
```

**优点**：同源 → 无 CORS、无跨域导航、无混合内容；流式转发 → 大文件不 OOM；可统一注入 Token；浏览器原生下载支持进度和断点续传
**缺点**：需要自己的服务器带宽；代理需能访问目标域名

## 方案五：原生 `DownloadManager`（安卓 WebView 唯一正解）

**适用**：安卓 WebView / 混合 App。前端把 URL 交给原生，剩下的原生全包。

### 前端

```typescript
interface AndroidBridge {
  downloadFile(url: string, fileName: string, token?: string): void;
}

async function downloadInWebView(
  fetchUrl: () => Promise<{ url: string; fileName: string; token?: string }>
): Promise<void> {
  const { url, fileName, token } = await fetchUrl();

  const bridge = (window as unknown as { AndroidBridge?: AndroidBridge }).AndroidBridge;
  if (bridge?.downloadFile) {
    bridge.downloadFile(url, fileName, token);
    return;
  }

  // 降级：普通浏览器用 blob 方案
  await downloadByBlob(async () => ({ url, token }), fileName);
}
```

### 原生（Java）

```java
@JavascriptInterface
public void downloadFile(String url, String fileName, String token) {
    DownloadManager.Request request = new DownloadManager.Request(Uri.parse(url));
    if (token != null && !token.isEmpty()) {
        request.addRequestHeader("Authorization", "Bearer " + token);
    }
    request.setTitle(fileName);
    request.setDescription("正在下载...");
    request.setNotificationVisibility(
        DownloadManager.Request.VISIBILITY_VISIBLE_NOTIFY_COMPLETED);
    request.setDestinationInExternalPublicDir(
        Environment.DIRECTORY_DOWNLOADS, fileName);

    DownloadManager dm = (DownloadManager) getSystemService(Context.DOWNLOAD_SERVICE);
    dm.enqueue(request);
}
```

**优点**：大文件不 OOM、后台下载、系统通知、支持 Header、支持断点续传
**缺点**：需原生配合
**这是安卓 WebView 的最终方案。**

## 方案六：Streams + File System Access（Chrome 桌面大文件）

**适用**：Chrome/Edge 桌面，大文件，需要带 Header，不想走服务端代理。

```typescript
async function downloadByStream(
  fetchUrl: () => Promise<{ url: string; fileName: string; token?: string }>
): Promise<void> {
  const { url, fileName, token } = await fetchUrl();

  const response = await fetch(url, {
    headers: token ? { Authorization: `Bearer ${token}` } : {},
  });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);

  // 让用户选保存位置（必须用户手势触发）
  const fileHandle = await (window as any).showSaveFilePicker({
    suggestedName: fileName,
  });
  const writable = await fileHandle.createWritable();

  // 流式读取，分块写入，内存恒定
  const reader = response.body!.getReader();
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    await writable.write(value);
  }
  await writable.close();
}
```

**优点**：大文件不 OOM、能带 Header、能显示进度
**缺点**：只有 Chromium 桌面支持、安卓 WebView 不支持、需用户选保存位置

## 决策表

| 场景 | 推荐方案 | 大文件 | 能改名 | 能带 Token | 防拦截 |
|------|---------|--------|--------|-----------|--------|
| 普通浏览器 + 小文件 + CORS 允许 | **方案一 Blob** | ❌ | ✅ | ✅ | ✅ |
| 普通浏览器 + 大文件 + 后端可配合 | **方案二 a 标签 + CD** | ✅ | ⚠️ | ❌ | ✅ |
| 跨域 + 大文件 + 带 Token | **方案四 服务端代理** | ✅ | ✅ | ✅ | ✅ |
| 安卓 WebView | **方案五 原生 DownloadManager** | ✅ | ✅ | ✅ | ✅ |
| Chrome 桌面 + 大文件 + 带 Token | **方案六 Streams + FS** | ✅ | ✅ | ✅ | ✅ |
| 需要窗口引用 | 方案三 window.open | ⚠️ | ⚠️ | ⚠️ | ❌ 易拦 |

## 通用封装（自动选最优方案）

```typescript
interface DownloadResult {
  url: string;
  fileName: string;
  token?: string;
}

/**
 * 智能下载：点击 → 异步拿 URL → 自动选择最优下载方式
 */
async function smartDownload(
  fetchUrl: () => Promise<DownloadResult>
): Promise<void> {
  const { url, fileName, token } = await fetchUrl();

  // 1. 安卓 WebView：优先原生
  const bridge = (window as any).AndroidBridge;
  if (bridge?.downloadFile) {
    bridge.downloadFile(url, fileName, token);
    return;
  }

  // 2. 判断是否需要 fetch（有 token 或需要 CORS 读取）
  if (token) {
    try {
      await downloadByBlob(async () => ({ url, token }), fileName);
      return;
    } catch (e) {
      console.warn('Blob 下载失败，降级 a 标签', e);
    }
  }

  // 3. 无 token：a 标签直下（依赖后端 Content-Disposition）
  const a = document.createElement('a');
  a.href = url;
  a.download = fileName;
  // 不加 target="_blank"（避免跨源导航拦截）
  a.style.display = 'none';
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
}
```

## 关键防拦截清单

| 坑 | 正确做法 |
|----|---------|
| `window.open` 在 `await` 后调用返回 `null` | 先同步开窗口，再异步导航；或干脆不用 |
| `a` 标签加 `target="_blank"` 跨域被拦 | **去掉 `target="_blank"`** |
| 跨域 `a.download` 失效 | 后端返回 `Content-Disposition: attachment`，或走 `fetch + Blob` |
| `fetch` 跨域被 CORS 拦 | 后端配 `Access-Control-Allow-Origin`，或走服务端代理 |
| HTTPS 页面下载 HTTP 被混合内容拦 | 用代理中转，或后端改成 HTTPS |
| 大文件 `Blob` OOM | 用 `a` 标签直下、服务端代理、原生 DownloadManager |
| `blob:` URL 未释放内存泄漏 | `URL.revokeObjectURL()`，延迟 1~3 秒 |

---

## 一句话选型

- **小文件、能 CORS** → 方案一 `fetch + Blob`
- **大文件、后端能配合** → 方案二 `a` 标签 + `Content-Disposition`
- **跨域 + 大文件 + 带 Token** → 方案四 服务端代理
- **安卓 WebView** → 方案五 原生 `DownloadManager`
- **Chrome 桌面大文件** → 方案六 Streams + File System Access

**最省心的组合**：让后端在下载地址返回 `Content-Disposition: attachment`，前端用 **方案二**（`a` 标签，不加 `target`），异步拿 URL 后直接点击。**简单、不占内存、不拦截、支持大文件。**
